# License Lens — 依赖升级合规差异审查

在原有许可证看板之上，增加"依赖升级合规差异审查"工作流。数据、规则、界面三层分离，**不增加任何 npm 依赖**。

## 目录结构

```
src/
  domain/types.ts     数据层：领域模型（依赖 / 版本 / 候选 / 引用路径 / 授权 / 通知 / 批次 / 冲突）
  data/store.ts       数据层：localStorage 持久化 + 业务动作（只读写状态，不做合规判断）
  rules/compliance.ts 规则层：纯函数，R1–R7 全部合规判定
  ui/useStore.ts      界面层：React 订阅 hook
  App.tsx             界面层：总览 / 待处理通知 / 冻结批次 / 刷新冲突 四个视图
  styles.css          样式
scripts/verify.mts    R1–R7 端到端验证（npm run verify，复用 vite 自带的 rolldown，无新增依赖）
```

依赖方向固定为 `ui → data → rules → domain`；规则层不 import 数据层与界面层。

## 规则（与冲突行 `ruleCode` 对应）

| 编号 | 规则 | 行为 |
|---|---|---|
| R1 | 未审核候选版本不得替换当前版本 | "替换当前版本"按钮对未审核候选禁用；强制调用时 store 返回拒绝原因；刷新时若当前版本记录未审核同样报冲突 |
| R2 | 许可证 / 版权声明 / 来源变化进入复核 | 候选版本与当前版本逐字段 diff，差异列入活清单；复核通过后通知消失（审核人/时间留痕） |
| R3 | GPL 系（GPL-2.0/3.0、LGPL、AGPL）由内部使用升级为对外分发 | 每个对外分发引用必须被**绑定当前版本且覆盖该引用路径**的法务授权覆盖，否则产生高风险通知与刷新冲突；授权按路径逐一绑定，可撤销 |
| R4 | 同一路径重复引用只保留一份义务 | 义务/通知按规范化路径去重；引用为软删除，最后一条移除后义务才收回；可重新登记 |
| R5 | 撤回只恢复最近的已审核版本 | 沿版本历史栈回退到最近的 reviewed 版本；被撤回版本标记 withdrawnAt；无已审核历史则拒绝 |
| R6 | 补录另建带原因版本 | 补录必须填写原因，新建独立版本记录，不覆盖既有记录、不改变当前版本 |
| R7 | 刷新一致性 | 以当前版本为准核对：当前版本是否已审核、授权版本是否匹配、授权覆盖路径是否仍存在、冻结批次快照与当前版本/许可证是否一致；冲突行包含**依赖、旧→新许可证、引用路径、命中规则**四要素 |

## 通知批次

- 活清单由当前状态实时派生：问题解决自动消失，撤销授权等变化自动出现。
- **冻结批次**对活清单做不可变快照（依赖、版本、许可证、路径、规则全文），冻结后活清单清空；之后任何撤回/补录/撤销都不会改写批次，只产生新条目或新批次。

## 持久化

全部状态写入 `localStorage`（键 `license-lens-v2`），刷新页面后依赖、路径、授权、批次与当前版本保持一致；旧键 `license-lens` 不再使用。

## 命令

```bash
npm run dev      开发
npm run build    类型检查 + 构建
npm run verify   R1–R7 端到端规则验证（39 项断言）
```
